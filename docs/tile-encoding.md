# 牌编码约定

本规范覆盖 `engine/` 内部所有牌相关数据结构。**规则引擎、网络协议、牌谱格式都必须遵守**，前端展示层例外（前端可任意映射到资源文件名）。

---

## 1. 牌的整数编码（0-33）

| 区间 | 牌 | 整数编码 |
|---|---|---|
| 万子 | 1m – 9m | 0 – 8 |
| 筒子 | 1p – 9p | 9 – 17 |
| 索子 | 1s – 9s | 18 – 26 |
| 字牌 | 东 南 西 北 白 发 中 | 27 – 33 |

具体到字牌：

| 牌 | 编码 |
|---|---|
| 东 (East)   | 27 |
| 南 (South)  | 28 |
| 西 (West)   | 29 |
| 北 (North)  | 30 |
| 白 (Haku)   | 31 |
| 发 (Hatsu)  | 32 |
| 中 (Chun)   | 33 |

**派生范围**：
- `is_manzu(t)` ↔ `0 ≤ t ≤ 8`
- `is_pinzu(t)` ↔ `9 ≤ t ≤ 17`
- `is_souzu(t)` ↔ `18 ≤ t ≤ 26`
- `is_honor(t)` ↔ `27 ≤ t ≤ 33`
- `is_wind(t)` ↔ `27 ≤ t ≤ 30`
- `is_dragon(t)` ↔ `31 ≤ t ≤ 33`
- `is_yaochuuhai(t)` ↔ 幺九牌 (1/9 of m/p/s, 27-33)
- `is_terminal(t)` ↔ 老头牌 (1/9 of m/p/s)

## 2. 手牌主表示：`counts: int[34]`

```python
counts: list[int]  # length == 34, values in 0..4
# counts[i] 表示编码 i 的牌当前有几张
```

- **所有快速判定（听牌、向听、役）必须在 counts 上做**，不要重新解析字符串
- 不变量：`0 ≤ counts[i] ≤ 4`，`sum(counts) ≤ 14`（含可能的副露后剩余手牌）
- 副露不计入 counts，单独用 `Meld` 列表存

---

## 3. 赤五（红宝牌）

**单独 `bool` 字段，不占编码位**。常见做法：

```python
@dataclass(frozen=True)
class Hand:
    counts: tuple[int, ...]        # length 34
    aka_5m: bool = False           # 是否含赤 5m
    aka_5p: bool = False           # 是否含赤 5p
    aka_5s: bool = False           # 是否含赤 5s
```

雀魂金之间默认每种五各 1 张赤五，共 3 张。具体数量以 `docs/rules.md` 为准。

**理由**：赤五在听牌/分解算法里和普通五完全等价，单独标志位避免污染 counts 数组，也避免把 `int` 牌型变成 `enum/tuple`。

## 4. 字符串表示（仅用于 IO）

人类可读 / 牌谱 / CLI 输出统一使用：

| 牌 | 字符串 |
|---|---|
| 1万 | `"1m"` |
| 5筒 | `"5p"` |
| 9索 | `"9s"` |
| 赤 5 万 | `"赤5m"` |
| 东 | `"东"`（或 `"E"`，二选一，**`docs/api.md` 定线**） |
| 南 | `"南"` / `"S"` |
| 西 | `"西"` / `"W"` |
| 北 | `"北"` / `"N"` |
| 白 | `"白"` / `"P"`（白板） |
| 发 | `"发"` / `"F"` |
| 中 | `"中"` / `"C"` |

> **TODO**：字牌字符串中英文形式二选一，在网络协议层确定。引擎内部用编码 0-33，不应触发该决定。

**多张牌**写法：空格分隔，`"1m 2m 3m 5p 赤5p 7p"`。

**何时用 counts，何时用字符串**：

| 场景 | 用 |
|---|---|
| 算法（听牌、分解、役、点数） | `counts` |
| 单元测试构造 | 字符串 → 通过 `parse_hand()` 转 counts |
| CLI 输出、日志、牌谱 | 字符串 |
| WebSocket 协议 | 字符串（人类可读，便于调试） |

## 5. 副露 (Meld) 表示

```python
class MeldType(Enum):
    CHI = "chi"        # 吃
    PON = "pon"        # 碰
    KAN_OPEN = "kan_open"     # 明杠（含大明杠 / 加杠两种来源）
    KAN_CLOSED = "kan_closed" # 暗杠

@dataclass(frozen=True)
class Meld:
    type: MeldType
    tiles: tuple[int, ...]      # 长度 3 (吃/碰) 或 4 (杠)
    called_from: int | None     # 被吃/碰/杠的玩家相对座位 (0=自家暗杠时为 None)
    called_tile: int | None     # 被叫的那张牌（用于判定大明杠 vs 加杠）
    contains_aka: bool = False  # 是否含赤五
```

加杠 vs 大明杠的区分：

- **加杠**：从已存在的 `PON` 中升级，保留原 `called_from`，新加的牌是自家摸来的
- **大明杠**：直接对他家打出的牌开杠，`tiles[0]` 为被叫牌

具体实现细节在 M1 `hand.py` 中落地。

## 6. 全集与计数

- 4 人麻将牌山 **136 张**：34 种 × 4 张
- 3 人麻将牌山 **108 张**：去掉万子 2-8（即编码 1-7），保留 1m 和 9m
- 赤五替换：每个五（编码 4 / 13 / 22）中随机一张替换为赤五标志（雀魂规则下数量与位置在 `docs/rules.md` 第 2 节明确）

---

## 7. 字典序与遍历

枚举所有牌时统一按编码 0→33 顺序。手牌输出字符串时同样按编码升序，保证不同来源生成的字符串可直接比较。
